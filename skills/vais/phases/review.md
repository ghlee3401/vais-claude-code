# Review

## 절차

1. `docs/{feature}/plan.md`의 **완료 조건을 하나씩 대조** — 각 항목 충족/미충족 판정 (실행 가능한 것은 실행해서 확인).
2. 전체 테스트 실행 + 빌드/린트 확인.
3. 코드 품질 점검 — 변경분에 대해 `qa-engineer` 위임 또는 직접: 버그 패턴, 지침 위반, 놓친 엣지 케이스.
4. 보안 관련 변경(인증/입력 처리/시크릿/의존성 추가)이 있으면 `security-auditor` 위임 (옵션 — 해당 없으면 스킵하고 그 사실을 review.md에 명기).
5. `docs/{feature}/review.md` 작성 (`templates/review.template.md`, ≤60줄):
   - 완료 조건 대조 결과 (충족 n/m + 미충족 사유)
   - 남은 일 (미충족 항목 + 후속 과제)
   - 교훈 (승격 후보 표시)
6. **승격 루프 (필수 마지막 스텝)** — `notes.md` + 교훈을 훑고 "앞으로 반복 적용할 규칙이 있는가?" 판단:
   - 있으면 `guidelines/*.md`에 한 줄 추가 (예산 초과 시 하나 제거) → `review.md`에 `승격: {요지} → {파일}` 기록
   - 없으면 `승격: 없음` 기록
7. status 갱신 — 완료 조건 전부 충족 시 피처 완료 처리.

## 규칙

- 미충족 항목이 있으면 완료 처리하지 않는다 — 사용자에게 보고하고 do 재진입 또는 범위 조정을 선택받는다.
- review 단계에서 기능 추가 금지 — 수정은 결함 교정만.

## 완료 시

대조 결과(n/m)와 승격 여부를 대화에 표시 → 완료 또는 `/vais do {feature}` 재진입 제안.
