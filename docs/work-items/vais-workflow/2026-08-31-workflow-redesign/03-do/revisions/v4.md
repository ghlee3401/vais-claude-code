# Do revision 4 — Fair comparison adapter

## 변경

Design revision 4의 prompt 동등성·격리·고정 순서·실패 판정 계약을 evaluation 경로에 구현했다. production v2 runtime과 `workflowV2.mode: shadow`는 변경하지 않았다.

| 영역 | 구현 결과 |
|---|---|
| Canonical workload | 기능 요구사항·완료 조건·승인 결정을 immutable JSON 한 건으로 고정하고 Mini Booking fixture digest 결속 |
| Prompt adapter | Legacy/v2가 같은 semantic payload digest를 공유하고 공개 route·Phase·revision 문법만 다르게 render |
| 원문 보호 | raw prompt를 평가 evidence에 저장하지 않고 workload·adapter code·rendered prompt digest로 재현 |
| Legacy stage | dirty worktree가 아니라 승인된 Git `HEAD` tree에서 self-contained Legacy plugin stage 생성 |
| Legacy runner | `/vais cto plan→design→do→qa→report` 5-turn native 여정과 provider telemetry·Agent count·문서·상태 결속 |
| v2 runner | 4-turn 자동 여정에 같은 workload/adapter 증거와 전체 journey budget 잔액 차감 적용 |
| Paired runner | `L1→v2-1→L2→v2-2→L3→v2-3`, 새 project/session, 대체 repetition 금지를 강제 |
| Trusted aggregator | schema 2.1에서 workload, 순서, model, effort, tool profile, budget, adapter proof와 실제 user turn 수 검증 |

| 공통 품질 | 양쪽 모두 신뢰된 외부 Chrome observer의 동일 5개 시나리오 결과를 terminal quality에 결속 |

## Formal Attempt와 보완

첫 formal cohort는 `Legacy 1` 전체 여정을 완료한 뒤 `v2 1` 시작 직후 중단했다. Legacy 1의 실제 결과는 terminal completed, Chrome 5/5와 QA 문서 PASS였지만, 초기 adapter가 Legacy native string phase 상태에 별도 `qaVerdict` 필드가 없다는 이유로 quality fail을 기록했다.

이는 제품 품질 실패가 아니라 evidence adapter 결함이다. Design revision 4 규칙에 따라 같은 cohort의 나머지 실행과 replacement repetition을 중단하고 원시 결과를 `/tmp/vais-rev4-formal.zcH15H`에 보존했다. 이후 상태 자기보고에 의존하지 않도록 양쪽 runner에 동일한 외부 Chrome observer를 추가했다. 보완 observer로 기존 Legacy 1을 재검사한 결과 5/5 PASS였지만, 이 재검사는 중단된 cohort를 formal PASS로 승격하지 않는다.

| Legacy 1 관측 | 값 |
|---|---:|
| terminal | completed |
| formal user turns | 5 |
| cache-creation tokens | 162,880 |
| elapsed | 601,728 ms |
| provider list cost | $3.3819068 |

| 공통 Chrome observer 재검사 | 5/5 PASS |

`v2 1`은 첫 provider capture가 확정되기 전에 중단되어 formal 표본으로 사용하지 않는다. 중단 전 provider 비용은 raw JSON이 없어 관측 불가이며 Legacy 1 비용에 합산하거나 0으로 간주하지 않는다.
