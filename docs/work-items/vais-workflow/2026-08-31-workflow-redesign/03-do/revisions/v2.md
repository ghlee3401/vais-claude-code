# Do — Lean Phase Transactions

## 변경

Design revision 2의 실행 효율 개선을 구현했다. 이전 구현·repair 상세는 [revision 1](./v1.md)에 보존했다.

| 영역 | 구현 |
|---|---|
| Context | Phase별 필요한 REQ·TC·scope·receipt만 담는 크기 제한 capsule과 stale hash 검증 |
| Phase 종료 | `plan present`, `design present`, `do ready`, `review decide`, `report finalize` transaction |
| Agent | Design 선택 specialist만 assignment하고 Agent 종료 hook이 handoff를 검증·자동 저장 |
| 문서 | 규모별 byte budget과 선행 Phase 장문 복제 검사 |
| QA telemetry | 모든 provider model의 cache-creation 합산, formal 여정과 quota/attack 진단 turn 분리 |
| 호환성 | 기존 세분화 CLI는 rollback 경로로 유지하고 v2-only staged bundle에 새 runtime만 포함 |
| 실행 무결성 | 현재 session·Work item·phase·명시 revision 재검증, 성공 evidence 사전 준비 후 상태 commit |
| 승인 | 문장 시작의 명시 승인만 처리하고 조건부·부정·대리·stale revision과 임의 suffix는 비변경 거부 |
| 반복 QA | assignment·handoff를 Design revision과 repair cycle에 함께 결속해 이전 QA 결과 재사용 차단 |
| 평가 증거 | immutable stage/model/effort/tool profile과 raw telemetry·Agent·문서 manifest의 경로·SHA-256 재계산 |

주요 경로는 `lib/workflow/v2/`, `hooks/workflow-v2-*.js`, `scripts/vais-workflow-v2.js`, `scripts/evaluation/`, `schemas/`다. 사용자-facing 동작이나 Plan 범위는 바꾸지 않았다.

## Handoff receipt

- 통합 과정에서 Agent PostToolUse 순서, staged bundle schema, runtime guidance와 evaluator 집계를 연결했다.
