# Do revision 3 — Assurance-aware efficiency

## 변경

Design revision 3의 효율 계약과 확인된 순수 낭비 제거를 구현했다. 다섯 Phase, 사용자 승인, 독립 QA, scope·lease·drift·repairCycle·rollback과 Report freeze는 유지했다.

| 영역 | 구현 결과 |
|---|---|
| Review check | `adapter + normalized command + Design revision + repo digest` identity와 immutable receipt 추가 |
| 단일 실행 | `review prepare`가 check를 한 번 준비하고, 동시 claim으로 같은 identity의 중복 실행을 차단하며 `review decide`는 receipt만 재사용 |
| 자동 진행 | Do READY receipt와 runtime 안내가 Review evidence·독립 QA까지 사용자 진행 turn 없이 계속하도록 연결 |
| draft | canonical promotion 때 transient Markdown을 정리하고 전역 `docs/**/draft.md`·`.vais/**/draft*.md`와 symlink draft를 Report 전에 차단 |
| 문서 preflight | deterministic frontmatter와 body를 canonical write 전에 메모리에서 section·trace·budget·repetition 검사 |
| QA handoff | compact/standard/extended를 3KB/5KB/8KB로 제한하고 로그는 digest·경로로 참조 |
| snapshot | canonical 상태·index write 뒤 Phase transaction당 최종 snapshot 한 건을 원자적으로 기록하고 capture 실패도 전체 rollback |
| 평가 | Delivery·Assurance·Diagnostic compute와 elapsed/cache read/output/list cost를 raw provider evidence에서 재계산 |
| 효율 Gate | Quality 선판정 뒤 EFF-01~08을 각각 판정하고 total/assurance/cost는 OBSERVE로 공개 |
| 실제 collector | 4 user-turn v2 runner와 trusted 3×2 aggregator를 추가하고 실제 stage·tool profile·raw/Agent/check/document manifest를 결속 |
| 배포 stage | production dependency closure를 link-free로 복사해 저장소 `node_modules`에 의존하지 않는 immutable v2 bundle 생성 |

주요 신규 경로는 `lib/workflow/v2/check-evidence.js`, `lib/workflow/v2/draft-lifecycle.js`, `schemas/review-evidence-prepare.schema.json`이다. 기존 phase transaction, document manager/check/quality, automatic handoff, prompt/drift hook, live evaluation scripts와 schema를 연결했다.

## Evidence와 구현 판단

- Do readiness와 Review가 같은 check를 요구하면 동일 identity의 receipt를 재사용한다. revision 또는 product snapshot이 달라지면 stale로 거부한다.
- Review evidence가 missing이면 `review decide`는 check를 실행해 숨기지 않고 fail closed한다.
- independent QA는 runtime 소유 raw evidence·diff·화면을 판단하며 구현자 자기보고를 사용하지 않는다.
- combined provider turn의 Assurance 분리는 compact formal 여정에서 independent QA가 유일한 Agent일 때만 허용한다. 다른 specialist가 섞이면 정확한 귀속이 불가능하므로 evidence를 `BLOCKED` 처리한다.
- canonical preflight 실패는 구조화 finding만 기록하고 신규 `main.md`를 생성하거나 기존 정본을 덮어쓰지 않는다.
- supplemental check는 QA가 명시한 이유와 같은 identity에 한 번만 허용하며 기존 PASS를 재실행할 수 없다.
- check execution claim과 receipt 저장을 같은 lock 경계에 두고, event가 current Design revision·command·repo digest를 직접 보존한다.
- aggregator는 정확히 한 Work item root 아래 다섯 Phase main만 authored로 세고, 누락·분산·중복·외부 symlink·빈 raw capture·argv profile 공격을 fail closed한다.
- staged v2 bundle에 새 Review evidence schema와 link-free production dependency를 포함했다.

## 남은 제한

- trusted aggregator와 v2 runner는 준비됐지만 Legacy가 `legacy-journey-evidence/v1`을 만드는 adapter는 아직 없다.
- Legacy는 `/vais cto plan ...`식 phase 명령을, v2는 `/vais {자연어 요청}`을 공개 진입점으로 사용하므로 Design §3.2의 **문자열까지 동일한 prompt**는 양쪽에서 동시에 정상 라우팅되지 않는다. 이를 몰래 변형하지 않고 Review 차단 사유로 남긴다.
- source 설정은 `workflowV2.mode: shadow`를 유지했고 실제 Opus formal 3×2 cohort는 실행하지 않았다.
