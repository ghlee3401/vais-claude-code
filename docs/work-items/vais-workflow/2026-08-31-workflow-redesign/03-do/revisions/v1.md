# Do — VAIS workflow redesign

## 구현 결과

승인된 Design의 여섯 Wave를 구현했다. 새 엔진은 기존 동작을 보존하는 `shadow` 모드이며, 독립 QA와 사용자 최종 승인 전에는 `/vais` 강제를 활성화하지 않는다.

| Wave | 결과 | 주요 경로 |
|---|---|---|
| 0~1 | v2 계약, event 상태 머신, binary Gate, 원자적 Work item 저장소 | `schemas/`, `lib/workflow/v2/` |
| 2 | `/vais` router, session authorization, 단일 lease, pending request, write guard | `hooks/workflow-v2-*`, `scripts/vais-workflow-v2.js` |
| 3 | 정본 문서·revision·Master, history resolver, 최소 Context View, 구조화 handoff | `lib/workflow/v2/` |
| 4 | C-Level·specialist 경량 역할 카드, 하나의 runtime specialist, 기계적 검사 adapter | `contracts/v2-role-cards.json`, `agents/v2-specialist.md` |
| 5 | Mini Booking 로그인·재설정·예약 UI와 실제 Chrome QA | `tests/fixtures/mini-booking/`, `scripts/evaluation/mini-booking-browser.js` |
| 6 | Legacy/v2 Shadow 비교와 실제 host 증거가 없을 때 BLOCKED하는 평가기 | `lib/evaluation/v2-shadow.js`, `tests/fixtures/v2-shadow-scenarios.json` |

## 핵심 구현 결정

- 기존 `/vais` Skill 본문은 `skills/vais/legacy.md`로 보존했다. 새 진입 Skill은 설정에 따라 Legacy 또는 v2로 분기한다.
- v2 specialist는 Agent별 Markdown을 만들지 않고 `v2-specialist` 하나에 짧은 역할 프롬프트와 schema-valid assignment를 주입한다.
- 사용자 승인, 상태 전이, retry 제한, Report freeze와 write scope는 자연어 관례가 아니라 런타임이 강제한다.
- Design이 승인한 `writeScopes`가 Do authorization으로 전달되며 assignment가 이를 넓힐 수 없다.
- `QA` 단계 명칭은 동결된 설계에 따라 `Review`로 통일했다. Independent QA는 제품 코드를 수정할 수 없다.
- `js-yaml`과 취약한 하위 의존성을 안전 버전으로 갱신했다.

## QA repair 2 구현

Independent QA attempt 2가 실제 CLI와 Hook을 공격적으로 재현하며 찾은 추가 결함을 승인된 기술 범위 안에서 보완했다.

| 영역 | 보완 |
|---|---|
| Gate provenance | Plan·Design·Review·Report 정본 검사를 runtime이 다시 계산하고, readiness/Review Tool 검사는 Design 선언 목록·고정 adapter·내부 receipt가 모두 일치할 때만 수용 |
| stale evidence | Tool receipt를 승인된 제품 write scope의 repo fingerprint에 결합해 검사 뒤 코드가 바뀌면 Gate에서 거부 |
| 상태 원자성·감사 | 정본 쓰기 실패 시 registry 전이를 남기지 않고 rollback하며, 불법 전이는 failed audit event로 보존 |
| authorization | 현재 Work item·phase·active status·lease·정확한 allowed paths를 매 mutation 직전에 재검증 |
| 보호 경로 | `./`·역슬래시·중복 slash를 정규화한 뒤 `.vais`, `.git`, Work item/Feature/Master namespace를 Design product scope에서 거부 |
| Shell/Agent 우회 | `git --output`, `find -fls`, eslint fix/output/cache, Node reporter destination과 임의 동명 workflow script를 차단; specialist assignment는 runtime issuance receipt 필수 |
| drift | 모든 진행 Phase의 managed turn에서 비교하고, routing 실패 시 baseline을 소비하지 않으며 Gate 직후 최초 snapshot을 고정 |
| 문서 lifecycle | Plan·Design 승인 정본을 `approved`로 바꾸고 material revision을 Work item에 동기화하며 Report 정본을 완료 시 freeze |
| Review/Report | Review 정본에 REQ·TC·입출력·기대/실제·제한·evidence를 강제하고, Report 완료 전 Feature/Master 링크를 검사한 뒤 completed 상태로 재동기화 |
| staging | v2 bundle의 MCP runner·lazy UI knowledge를 포함하고 dangling Legacy link를 제거 |
