# Do revision 9 — deterministic QA handoff shape caps

## 변경

Review Attempt 13에서 explicit 2KB target을 받은 QA 모델이 3,086B를 생성해 3,072B hard limit을 14B 초과한 결함을 보완했다. 생성 모델의 byte 추정에 의존하지 않고 발급 schema가 출력 최대 구조를 제한하며, Design의 규모별 3KB/5KB/8KB 한도와 fail-closed 정책은 유지했다.

| 영역 | 구현 결과 |
|---|---|
| Shape policy | scale별 judgment `maxLength`, 배열 `maxItems`, item `maxLength`를 output schema에 주입 |
| Compact bound | judgment 80자, decisions 2×25자, behavior 배열별 2×20자, evidence 2×100자 등으로 제한 |
| Worst-case proof | 4-byte Unicode를 모든 허용 필드 최대치로 채워도 compact JSON이 3,072B 미만 |
| Runtime binding | base handoff schema뿐 아니라 digest로 결속된 assignment `outputContract`도 자동 저장 전에 검증 |
| Error handling | shape·byte 위반 모두 수동 저장이나 `SendMessage` 우회 없이 fail closed |
| Scope | public API·상태 전이·formal workload·adapter·3KB hard limit은 변경 없음 |
