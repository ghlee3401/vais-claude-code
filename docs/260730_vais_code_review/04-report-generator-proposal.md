# 04. 신규 기능 제안 — 보고서/슬라이드 생성기

> 요구: "디자인과 구성이 좋은 PPT나 HTML 보고서. AI한테 만들어달라고 하면 AI스럽게 나오는 문제 해결."
> 결론: **이미 보유한 자산(design-system/brands 71종 + MCP 서버)이 이 기능의 핵심 재료다.** 신규 개발량은 스킬 1개 + 템플릿 3개 + 체크리스트 1개 수준.

## 1. "AI스러움"의 정체 — 무엇을 막아야 하는가

AI 산출물이 AI스럽게 보이는 원인은 열거 가능하다. 막을 대상을 명시해야 규칙으로 강제할 수 있다:

| # | AI-slop 패턴 | 대체 규칙 |
|---|-------------|----------|
| 1 | 보라-파랑 그라데이션 히어로 + 글래스모피즘 | 브랜드 토큰 색만 사용 (DESIGN.md의 colors). 그라데이션 금지 기본값 |
| 2 | 모든 불릿에 이모지 (🚀✨💡) | 이모지 사용 금지. 아이콘 필요 시 단색 SVG 인라인 |
| 3 | 3-column 카드 그리드 반복 (모든 섹션이 같은 레이아웃) | 섹션별 레이아웃 변화 의무 — 표/타임라인/큰 숫자/2단 비교 등 콘텐츠 형태에 맞는 레이아웃 선택 |
| 4 | 내용 없는 수식어 ("혁신적인", "강력한", "seamless") | 숫자·고유명사·비교 없는 형용사 문장 금지 |
| 5 | 폰트 위계 부재 (전부 비슷한 크기 + 굵기 남발) | 타이포 스케일 고정 (예: 12/14/17/22/28/40, 1.25 ratio). 페이지당 굵기 3단계 이하 |
| 6 | 정보 밀도 극단 (텅 빈 슬라이드 or 벽면 텍스트) | 슬라이드당 1 메시지 + 근거 1개. 보고서는 표·차트가 본문의 30% 이상 |
| 7 | 차트 기본 색상 (plotly 기본 파랑, excel 무지개) | 브랜드 palette에서 파생한 categorical 색상만. 차트 스타일 단일 시스템 |
| 8 | 한국어 조판 무시 (어절 중간 줄바꿈, 좁은 행간) | `word-break: keep-all`, `line-height: 1.6+`, 국문 폰트 스택 명시 |

## 2. 명령 설계

| 명령 | 산출물 | 용도 |
|------|--------|------|
| `/vais report {주제\|피처}` | 단일 HTML 문서 (자체 포함, 인쇄 CSS 포함) | 기술 보고서, 분석 보고서, 프로젝트 완료 보고 |
| `/vais deck {주제\|피처}` | 16:9 HTML 슬라이드 (키보드 내비 + `@media print` → PDF) | 발표 자료. PDF로 내보내면 사실상 PPT 대체 |
| `/vais deck {주제} --pptx` | 위 + `pptxgenjs` 스크립트로 진짜 .pptx 생성 (옵션) | PPT 파일이 꼭 필요한 경우 |

**pptx 전략**: HTML-first를 기본으로 권장. 이유 — (1) HTML은 모델이 픽셀 수준까지 제어 가능해 디자인 품질 상한이 높고, (2) .pptx 직접 생성은 라이브러리 표현력 한계로 오히려 AI스러운 결과가 나오기 쉬움. pptx는 "편집 가능해야 하는 경우"의 옵션 경로로만.

## 3. 파이프라인 (내용 우선, 디자인은 마지막)

```
① 소재 수집     docs/{feature}/ 산출물, git log, 코드, 또는 사용자 제공 자료
② 아웃라인      스토리라인 + 슬라이드/섹션 목록 → AskUserQuestion 1회 승인
                (디자인 이전에 구성을 확정 — "구성이 좋은"의 절반은 여기서 결정됨)
③ 스타일 결정    brands/{slug}/DESIGN.md 선택 (기존 ui-designer의 brand 선택 UX 재사용)
                → colors/typography/spacing 토큰 추출
④ 생성          templates/report-html/ 스켈레톤 + 토큰 주입 + §1 금지 규칙 적용
⑤ 디자인 QA     self-critique 패스: §1 체크리스트 8항 + 대비(WCAG AA) + 오버플로 검사
                → 위반 항목 수정 후 완료
```

핵심 설계 판단 2가지:

- **② 아웃라인 승인이 유일한 중간 확인점** — 03 권고안의 "의식 최소화" 원칙과 일치. 구성이 틀리면 디자인이 좋아도 무의미하므로 여기 1회만 사용자 개입.
- **⑤ QA를 별도 패스로 분리** — 생성과 동시에 규칙을 지키게 하는 것보다, 생성 후 체크리스트로 자기 검증시키는 것이 준수율이 높다 (기존 qa-engineer 패턴의 축소 적용).

## 4. 파일 구조 (신규 개발분)

```
skills/report/
├── SKILL.md                    # 진입점 — 파이프라인 5단계 + 금지 규칙 8항 (≤4KB)
├── design-rules.md             # §1 표의 상세판 + 타이포 스케일 + 차트 색상 공식 (lazy-load)
└── templates/
    ├── report.html             # 보고서 스켈레톤 — 인라인 CSS, 토큰 변수 슬롯, 인쇄 CSS
    ├── deck.html               # 슬라이드 스켈레톤 — 16:9 섹션, 키보드 내비, @media print
    └── export-pptx.js          # (옵션) pptxgenjs 변환 스크립트
```

기존 자산 재사용:

| 기존 자산 | 재사용 방식 |
|-----------|------------|
| `design-system/brands/{slug}/DESIGN.md` | 색/타이포/컴포넌트 토큰의 single source — **이 기능이 brands 투자의 두 번째 소비자가 되어 유지 명분 강화** |
| `mcp design_search` | 주제·업종에 맞는 브랜드 스타일 추천 |
| `lib/status.js > getBrand/setBrand` | 피처당 브랜드 일관성 (개발 UI와 보고서가 같은 브랜드) |
| `vendor/ui-ux-pro-max` | 디자인 패턴 검색 (design phase와 동일 경로) |
| `docs/{feature}/` 이력 | 보고서 소재 — **"이력을 남기는 개발"의 최종 회수 지점**: 쌓인 이력이 보고서가 됨 |

## 5. 스켈레톤 품질 요건 (templates/report.html 기준)

- 자체 포함 (외부 CDN 의존 금지 — 오프라인/사내망 열람 가능)
- CSS 변수로 토큰 슬롯화: `--color-primary`, `--font-heading`, `--scale-*` → DESIGN.md 값 주입
- 국문 조판 기본값: `word-break: keep-all; line-height: 1.65; font-feature-settings: "tnum"` (표 숫자 정렬)
- `@media print`: 페이지 나눔 제어(`break-inside: avoid`), A4 여백, 배경색 인쇄 지시
- 차트: 인라인 SVG 우선 (라이브러리 없이 막대/선/도넛 수준은 SVG 직접 생성 — 스타일 완전 제어)
- 다크/라이트: 보고서는 라이트 고정 권장 (인쇄 일관성), 덱은 브랜드 톤 따름

## 6. 개발 규모 추정

| 작업 | 규모 |
|------|------|
| SKILL.md + design-rules.md | 소 — 본 문서 §1~§3을 그대로 이식 |
| report.html / deck.html 스켈레톤 | 중 — 품질이 여기서 결정되므로 1~2회 반복 다듬기 필요 |
| brand 토큰 주입 로직 | 소 — DESIGN.md 파싱은 기존 코드 존재 |
| export-pptx.js | 소 (옵션, 후순위) |

**권고**: 03 권고안의 Phase 3에서 착수하되, 슬림화(Phase 1~2) 완료 전이라도 `skills/report/`는 독립 모듈이므로 병행 개발 가능. 첫 검증 대상으로 **본 리뷰(260730_vais_code_review)를 `/vais report`로 HTML화**하는 것을 제안 — dogfood 소재로 적절.
