1. 왜 재편했나

vais-code 는 "이력을 남기는 일관성 있는 개발"을 위해 만든 Claude Code 플러그인이다. 그러나 v1.1 시점의 실측 결과, 수단이었던 C-Suite 조직 시뮬레이션이 목적을 잠식하고 있었다. 세션을 여는 것만으로 약 7,300 토큰, phase 하나를 실행하면 실제 작업 전에 15,000–20,000 토큰이 프레임워크 로드에 소모됐고, 피처 하나가 문서 17개를 낳았다.

진단 한 줄: 조직 시뮬레이션이 수단에서 목적으로 뒤집혔다. 라우팅 승인·Decision Record·아웃트로 의식이 개발 흐름 자체를 끊고 있었다.

3. 재편 방향

이력(records)과 지침(norms)을 분리하고, review 마다 이력의 교훈을 지침으로 승격한다.

  • 이력 — 피처당 3파일 고정: plan.md(범위·완료 조건) → notes.md(결정 한 줄 append) → review.md(대조·교훈). 검색용이며, 다시 읽지 않아도 된다.
  • 지침 — guidelines/ 2파일(5KB 상한)만 매번 로드. 크기 예산제(1 추가 = 1 제거)를 validator 가 기계 검증.
  • 승격 루프 — review 마지막 스텝에서 "반복 적용할 규칙인가?"를 판단해 지침에 1줄 승격. 일관성은 지침이, 근거는 이력이 담당.
