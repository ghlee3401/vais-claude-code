# guidelines/ — 프로젝트 지침

> 개발 시 **매번 로드되는** 살아있는 규칙. 이력(docs/)과 달리 항상 작게 유지한다.

## 지침 메타 규칙 (지침의 지침)

1. **크기 예산제** — 각 파일은 명시된 상한(KB)을 넘지 않는다. 상한 초과 시 규칙 하나를 추가하려면 하나를 제거한다.
2. **검증 가능한 규칙만** — "깔끔하게" 같은 원칙 금지. grep/린트/육안으로 위반을 판정할 수 있는 문장만 쓴다. 기계로 잡을 수 있는 규칙은 지침이 아니라 린터/훅으로 보낸다.
3. **중복 기술 금지** — 같은 규칙은 한 파일에만 존재한다. 다른 문서(CLAUDE.md, SKILL.md)는 참조만 한다.
4. **승격 루프** — 새 규칙은 review 단계에서 `notes.md`의 교훈으로부터 승격된다. 근거 없는 규칙 추가 금지 (규칙마다 유래를 아는 상태 유지).

| 파일 | 담당 | 상한 |
|------|------|------|
| `code-conventions.md` | 코드 일관성 | 3KB |
| `doc-conventions.md` | 문서 일관성 + 승격 루프 절차 | 2KB |
| 디자인/스타일 | `design-system/brands/{slug}/DESIGN.md` + `skills/report/design-rules.md`가 담당 (여기 중복 금지) | — |
