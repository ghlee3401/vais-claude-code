# Doc Conventions

> 상한 2KB. 메타 규칙은 `guidelines/README.md`.

## 피처 문서 — 3파일 고정

경로: `docs/{feature}/` (피처명: 영문 kebab-case 2~4단어)

| 파일 | 시점 | 상한 | 내용 |
|------|------|------|------|
| `plan.md` | 착수 전 | **80줄** | 요청 원문 인용 → 범위(in/out) → 접근 방법 → 완료 조건 |
| `notes.md` | 작업 중 | 없음 (한 줄 단위) | 결정·발견을 `- YYYY-MM-DD: {한 줄}` 로 append only |
| `review.md` | 완료 후 | **60줄** | 검증 결과 → 남은 일 → 교훈(승격 후보 표시) |

- frontmatter는 2필드만: `feature`, `updated`. 그 외 필드 금지.
- 문서는 한국어, 기술 용어는 원어. 변경 이력 표 금지 — 이력은 git이 담당.
- 이 3파일 외의 문서 생성 금지. 큰 산출물(벤치마크 덤프 등)이 생기면 `docs/{feature}/assets/`에 두고 notes.md에서 링크.

## 쓰기 규칙

- **다음 개발자가 30초 안에 맥락을 잡는 것**이 문서의 목적. 완전한 기록이 아니라 요지.
- 결정은 근거와 함께 한 줄: `- 2026-07-30: CJS 유지 결정 — 기존 lib 전체가 CJS, 혼용 비용 > 이득`.
- 수식어 없는 사실 서술. 표는 3열 이하 우선.

## 승격 루프 (review 단계 마지막 스텝, 필수)

1. `notes.md`의 교훈 항목을 훑고 **"앞으로 반복 적용할 규칙이 있는가?"** 판단
2. 있으면 해당 지침 파일(`code-conventions.md` 또는 본 파일)에 한 줄 추가 — 크기 예산 초과 시 덜 중요한 규칙 하나 제거
3. `review.md`에 승격 여부를 기록: `승격: {규칙 요지} → code-conventions.md` 또는 `승격: 없음`

## 아카이브

- 완료 피처는 그대로 둔다. 구조가 바뀌어 참조 가치가 사라진 문서만 `docs/_archive/`로 이동.
